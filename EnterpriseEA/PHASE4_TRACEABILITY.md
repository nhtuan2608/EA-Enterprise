# Phase 4 Virtual Trader evidence boundary

Source: master specification v1.2, section 6, plus pending-order addendum v1.3 [spec](PENDING_ORDER_LIFECYCLE_SPEC.md) and [plan](PENDING_ORDER_LIFECYCLE_PLAN.md). `TradeManager/ExpectedPath.mqh` observes an attested trade after fill. `TradeManager/PendingOrderLifecycle.mqh` proposes the earlier pending-order state machine. Both are isolated from the EA shell. The corresponding Python fixture/oracle checks are synthetic.

No order, close, stop modification or trailing action is implemented. The observer-only EA shell now includes a read-only bounded runtime evidence adapter, but the Phase 4 expected-path and pending lifecycle modules remain isolated. The full offline suite passes 132 tests and the integrated observer EA compiles on MetaEditor build 6230 with 0 errors/0 warnings. An isolated MT5 tester run now produces versioned runtime JSON and audit artifacts and confirms a bounded seven-day account snapshot with new entries blocked. A second fresh-start run also succeeds, but tester sandbox recreation means persistent checkpoint survival is not proven. Pending lifecycle integration, execution scenarios, authoritative restart reconciliation and Paper parity remain unverified.
